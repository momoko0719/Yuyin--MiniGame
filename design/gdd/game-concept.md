# Game Concept: 《余音》(Yuyin / Lingering Sound)

*Created: 2026-08-31*
*Status: Draft*

---

## Elevator Pitch

> 一款古风江湖的节奏战斗游戏。你是一个以乐律入武的少年剑客，一路向北去杀灭你满门的人，
> 而你的每一刀都落在歌曲的拍子上。一首歌就是一场 BOSS 战。

**10 秒测试**：玩家听完知道自己要做什么——跟着音乐砍人，打 BOSS。

## Core Fantasy

**你在用一首歌杀人。**

不是"打架时放着音乐"，是刀落下的那一瞬间，物理上的沉和音乐上的准同时发生，
分不出哪个是哪个。玩家追求的不是最高伤害数字，是**"这一刀砍得太对了"**那种
说不出的顺。

这是别处得不到的东西：《怪物猎人》有刀刀到肉但音乐只是气氛；音游有踩点快感
但没有重量；Dead as Disco 有编舞感但打击轻。**中间那块——沉重的打击感 + 精准的
音乐咬合——没人占住。**

---

## Unique Hook

**像 Dead as Disco 那样每一击都踩在音乐上，也像《怪物猎人》那样刀刀到肉。**

关键的技术实现是：**顿帧（hitstop）的时长不用秒来定，用音符时值来定。**

一首 120 BPM 的歌，一拍 0.5 秒。轻击顿 1/16 拍、重击顿 1/8 拍、破防顿 1/4 拍、
终结技顿 3/8 拍（原型试玩后从 1/2 拍调轻——半拍在乐句中间触发时会打断律动感，
3/8 拍仍能明显感知到"沉"，但不再是硬生生一卡）。这样顿帧结束的那一刻正好落在
一个音符位置上——**那个"凝滞"既是打击感，也是节奏本身**。并且它自动适配任何
BPM，一套参数通吃所有曲目。

据调研，这个做法在同类游戏中尚未出现（Dead as Disco 用 BeatWarping 拉伸动画去
凑拍子，代价是顿帧不能做重）。**这是本项目最核心的技术假设**，已在原型中验证
成立（见 `prototypes/rhythm-feel/README.md`）。

第二层钩子：**每个对手用不同方式破坏你的节奏**，而不是靠武器数量堆内容。
详见 Pillar 4。

## Player Experience Analysis (MDA Framework)

### Target Aesthetics

| Aesthetic | Priority | How We Deliver It |
| ---- | ---- | ---- |
| **Sensation** (感官) | **1** | 顿帧、低频、受击反馈、命中与音乐的咬合。这是第一位的 |
| **Challenge** (挑战) | **2** | 读 BOSS 招式、逐场变难、武器精通 |
| **Fantasy** (幻想) | **3** | 江湖侠客、以乐入武、山河场景 |
| **Narrative** (叙事) | **4** | 复仇主线，师父之死，每个 BOSS 一个短篇 |
| **Expression** (表达) | 5 | 武器选择、导入自己的歌 |
| **Discovery** (发现) | 6 | 追查线索、拼出灭门真相 |
| **Submission** (放松) | N/A | 不是放松向游戏 |
| **Fellowship** (社交) | N/A | 单人游戏 |

### Key Dynamics（我们希望自然涌现的玩家行为）

- 玩家会**为了一首喜欢的歌反复重打同一场**，而不是打过就走
- 玩家会**主动关掉辅助**去追求全程踩准的爽感（而不是被强制）
- 玩家会**导入自己的歌**，并在社区分享"用某某歌打某个 BOSS"的片段
- 玩家会**重打已通关的对手**，因为不同 BOSS 干扰节奏的方式不同，体验不重复

### Core Mechanics

1. **踩拍战斗**：攻击、格挡、闪避全部吸附到歌曲拍子上；踩准是伤害与手感的乘数，不是及格线
2. **曲式即战斗结构**：前奏对峙 → 主歌读招攒气 → 副歌破防爆发 → 间奏转阶段 → 末段处决
3. **敌人 = 破坏节奏的方式**：每个 BOSS 用不同手段扰乱玩家的拍子（加速、减速、预判连段、人声干扰、静音）
4. **BOSS 掉落节奏型**：打赢一个人，学会他的节奏，解锁对应心法（不解锁新武器——见 Pillar 4）

## Player Motivation Profile

### Primary Psychological Needs

| Need | How This Game Satisfies It | Strength |
| ---- | ---- | ---- |
| **Autonomy** | 选武器、选歌、选打法；辅助可自由开关；导入自己的音乐 | Supporting |
| **Competence** | 从跟着师父的拍子，到不需要任何提示就能踩准；BOSS 从打不过到一气呵成 | **Core** |
| **Relatedness** | 对师父这个角色的情感投入；路上遇到的人 | Supporting |

### Player Type Appeal (Bartle)

- [x] **Achievers** — 通关每首曲子、精通每把武器、追求更高连段
- [x] **Explorers** — 试验不同武器 × 不同歌曲的组合；追查灭门真相
- [ ] **Socializers** — 单人游戏，无社交系统
- [ ] **Killers/Competitors** — **明确不服务**打榜型玩家

### Flow State Design

- **Onboarding**：第一关就是师父的考验。他是活的节拍器，在旁边敲刀鞘数拍，打错了会骂人。
  胜利条件不是打赢（打不赢），是**撑完整首曲子不乱一拍**。
- **难度爬升**：师父同行期辅助全开 → 师父死后辅助消失 → 后期敌人主动干扰节奏
- **反馈清晰度**：踩准了不是弹个"PERFECT"，是**这一刀更沉**（更长顿帧、更重低频、更炸的特效）
- **失败恢复**：被打死才算失败，重来一场。漏拍永远不导致失败

## Core Loop

### Moment-to-Moment (30 秒)

BOSS 踩着鼓点出招，起手动作本身落在拍子上，所以玩家能**同时用眼睛看见和耳朵听见**
下一击什么时候来。玩家在那一拍上做出反应：格挡、闪避、或抢先打断。接住了，
画面顿一下，金属撞击声压在鼓点上。连续接住攒"气"。

**判定分三档**（关键设计）：

| 玩家的操作 | 结果 |
| ---- | ---- |
| 完全没反应 | 挨打，扣血 |
| 挡了/闪了，但没踩在拍上 | **挡住了，不扣血**，但被推开、没有反击机会 |
| 踩准了 | 完美格挡，攒气，**开出反击窗口** |

**节奏决定你打得多狠，不决定你死不死。** 节奏差的玩家不会死得更快，只是打得更慢更被动。

### Short-Term (一场战斗 = 一首歌，约 3–5 分钟)

歌曲结构就是战斗结构：

| 曲式段落 | 战斗阶段 | 玩家在做什么 |
| ---- | ---- | ---- |
| 前奏 | 对峙、试探 | 读招、格挡、找到这首歌的感觉 |
| 主歌 | 攻防往来 | 稳扎稳打，攒气 |
| **副歌 / Drop** | **破防爆发窗口** | **全曲最燃处 = 倾泻连招，伤害翻倍** |
| 桥段 / 间奏 | BOSS 转阶段 | 慢下来，喘息，剧情 |
| 末段副歌 | 决胜 | 处决 |

### Session-Level (30–120 分钟)

2–4 场战斗，每场一首歌一个场景一个对手。自然停顿点在每场战斗之间。
故事模式一路向北推进；自由模式可以任选已解锁的曲目与武器重打。

### Long-Term Progression

**打赢一个人，学会他的节奏。** 每个 BOSS 解锁一种武器或心法：

- 老将（重兵器，最慢最重）→ 解锁**重剑**
- 同路人（快、密）→ 解锁**双刀**
- 乐师（变速）→ 解锁战斗中变速的心法
- 唱歌的女人（人声干扰）→ 解锁在干扰下守住板眼的被动

叙事上也通：他一路把仇人的东西一件件学过来，最后用这些东西去打韩铎。

### Retention Hooks

- **音乐**：玩家为了一首喜欢的歌回来（这是核心留存动力，不是附加）
- **重玩**：不同 BOSS 用不同方式破坏你的节奏，同一套操作打起来体验不重复
- **导歌**：玩家导入自己的曲子，内容无限
- **精通**：从需要辅助到全程裸打，可见的自我提升
- **好奇**：灭门真相一步步逼近

## Game Pillars

### Pillar 1: 节奏决定你打得多狠，不决定你死不死

漏拍只是伤害低、不进连段，绝不扣血、绝不 fail。防守判定给足宽容度：
反应了但没踩准，仍然挡得住。游戏负责让你踩上拍子，而不是考你能不能踩上。

*Design test*：在"更严格更公平的判定"和"更宽容的判定"之间，**永远选宽容**。

*依据*：Hi-Fi Rush 的设计原则是"漏拍不等于失败，无论何时按输入都会生效并被同步到
音乐上"；Dead as Disco 的 BeatWarping 是为了让主角"无论你节奏多烂，玩起来永远很酷"。
两个最成功的同类作品独立得出同一结论。

### Pillar 2: 一首歌就是一场战斗

曲式结构即战斗结构。任何新系统，先问它属于曲子的哪一段。

*Design test*：塞不进前奏/主歌/副歌/间奏任何一段的功能，**就不做**。

### Pillar 3: 刀刀到肉优先于编舞好看

顿帧、低频、受击反馈的优先级高于动作的连贯与美观。这是我们跟 Dead as Disco
最根本的分歧——它偏了编舞，打击轻。

*Design test*：当"动作更流畅漂亮"和"这一下更沉"冲突时，**选沉**。

*依据*：MH World 顿帧 13 帧@60fps、MH Rise 15 帧，均远超通用建议值（0.05–0.08 秒）。
MH Wilds 砍到 0 帧后，老玩家普遍反馈"轻飘"。顿帧就是打击感本身。

### Pillar 4: 每个对手改变节奏本身，不是数值

*（原「武器 = 音符密度和落点」已在原型试玩后废弃——单刀一拍一刀、双刀一拍
四刀，本质只是难度分级，不是玩法差异。真正独一无二的差异化来自对手，
不是武器。锁定一把武器，把手感调到极致，靠对手制造变化。）*

每个 BOSS 用自己的方式扰乱你已经建立的节奏感——加速你的心跳、拖慢到你想
断连段、预判你的连段、把拍子唱偏、甚至压过整首曲子直到静音。同一套操作，
打起来完全不同，因为对手在改变"这一拍意味着什么"，而不是"这一拍有几个音符"。

*Design test*：新 BOSS 如果只是血更厚、招更密，**就不该做**。它必须有一种
独特的"让你乱"的方式，且这种方式要能用一句话说清楚（"中毒后心跳加快"
"人声把拍子唱偏"）。

*依据*：《曲中剑》被批"攻击方向单调"，Dead as Disco 被批"一直按左键"——
两者的差异化都试图靠更多内容堆出来，都没做出"对手改变节奏"这个维度。

### Pillar 5: 情绪靠落差，不靠一路高能

慢歌不是休息，是让快歌更快的东西。

*Design test*：加新曲目时，先看它前后两首是什么，而不是它自己好不好听。

*依据*：《节奏医生》在紧张曲目中穿插抒情曲，是玩家记忆最深的设计；
Dead as Disco 被批评"全程高能、打三小时就腻"。

### Anti-Pillars (What This Game Is NOT)

- **NOT 复杂战斗系统**：不堆耐力条、卸势条、打药、多资源管理。
  《燕云十六声》的教训是系统一多，玩家就没法专注看敌人——而我们的玩家还要同时听音乐。
- **NOT 掉落音符的传统音游界面**：视线必须在敌人身上，不能在轨道上。
- **NOT 扣血式 miss 惩罚**：违反 Pillar 1。
- **NOT 开放世界**：一条线，从南到北，不折返。
- **NOT 多人游戏**。
- **NOT 打榜型硬核音游**：我们判定宽容、有辅助、还有顿帧打断节奏。
  想同时讨好硬核音游玩家会毁掉核心体验。

## Story and World

### 一句话

一个出身乐武门派的少年，在师父死后，独自一路向北，去杀那个当年下令灭他满门的人。

### 设定

**时代**：架空泛江湖，乱世。不考据具体年号。

**核心概念——板眼**：中国传统音乐里，强拍叫**板**，弱拍叫**眼**。"一板三眼"即四拍子。
成语"有板有眼"至今在用，意为有条理、合规矩。**沈家的武学就叫「板眼」**，
师父那句"不抢不拖"讲的就是这个（抢=抢板，拖=拖眼）。

**反派动机**：**韩铎**，以鼓令指挥部队的将领。他的野心是让一支军队像一个人一样动——
千人听同一个鼓点，同起同落。他听说江南有个小门派以乐律入武，凭一个拍子就能协同如
一体，正是他要的东西。他上门求谱，沈砚的父亲拒绝了，理由是：

> **这是一首曲子。曲子是给人听的，不是用来驱使人的。**

韩铎屠门夺谱，但**光有纸练不成**，得有人会奏。所以当他得知沈家还有活口正在北上，
他要的不是杀，是**抓活的**。这条轴串起了路上所有人。

**主题**：同一门东西，在父亲手里是曲子，在韩铎手里是军令。而沈砚一路把仇人的
节奏一件件学过来——**同样是拿别人的东西，一个学会了，一个只抢到了纸。**

### 主角：沈砚

十二岁那年满门被屠，被父亲塞进琴匣，从缝里听完了全程。他记得最清楚的不是惨叫，
是那个**节奏**：刀入肉的闷响，一下，一下，间隔一模一样，像有人在打拍子。

因为真的有人在打拍子——那不是江湖仇杀，是军队。江湖人杀人是乱的，军队杀人是齐的。

### 师父：段拙

独臂，父亲的师兄，那夜唯一的活口。把沈砚养到十九岁。

**他不是打不过，是撑不久。** 一炷香之内他还是绝顶高手，超过那个时间气力不继。
这解释了他为什么能教、为什么不让沈砚下山、以及最后为什么会死。

**让他成为一个真人的细节**（不是背景故事，是这些）：
- 数拍子会哼，而且跑调，七年来一直跑同一个地方
- 用刀鞘敲人后脑勺，敲了七年，位置分毫不差
- 独臂剥不了花生，每次喝酒都要沈砚给他剥，剥慢了就骂
- 开打前永远说同一句：**「不抢不拖。」** 说了七年，沈砚烦得要死

**机制上他就是节拍器**：他在场时屏幕有清晰的节拍提示，他在旁边敲刀鞘数拍，
抢拍了会出声骂。这不是教程 UI，是一个活人。

### 师父之死

渡口一战杀了韩铎的探子，等于报了信。那一夜师徒投宿雨中驿站，军队围了上来——
不是一个高手，是一队人，**按鼓令进攻，间隔均匀**。这是沈砚长大后第一次听见
序幕里那个节奏。

师父守门。他确实杀了很多人。**但对方从头到尾没打算打赢他，是来耗他的。**
鼓令不急不缓，一波一波，就是不停。

**这一场是玩家操作的。** 你和师父背靠背守门，整场战斗中你听着**师父敲的拍子
一点点不稳**——先慢半分，然后错开，然后接不上。你依赖了三场的那条节拍提示，
开始抖。等你回头，他还站着，靠着门框，人已经没了。

**段拙死于他自己讲了七年的那句话。** 一辈子怕"拖"，最后被人用"拖"耗死。
杀他的是节奏本身。

### 最后的回响

师父死后所有节拍提示消失。最终战中韩铎用军鼓压过曲子，直到彻底静音——
**那几十秒里玩家听见的，是那段跑调的哼声。**

### 关卡结构与曲目编排

按"专辑"来排，有起伏有留白，不是越来越快的歌单：

| 场次 | 场景 | 曲子 | 情绪 | 对手与机制 |
| ---- | ---- | ---- | ---- | ---- |
| 序 | 江南·雨夜 | 无乐，只有雨声和那个拍子 | 冷 | 不可玩，过场 |
| 一 | 山上·考验 | 中慢，箫笛起势渐入鼓点 | 清冷、教学 | 师父。撑完全曲不乱拍 |
| 二 | 江上·渡口 | 中快，硬派 | 第一次燃 | 探子。师父在旁数拍 |
| 三 | 雨夜·驿站 | 最烈 → 拍子渐乱 → 停 | 高潮 → 空 | 军队围攻，**师父死** |
| 四 | 竹林 | 变速：慢起渐快 | 阴、缠 | **乐师**（中年，用毒）→ 中毒后 BPM 逐段上升 |
| 五 | 雪山驿道 | 最慢最重，鼓为主 | 沉、恨 | **老将**（老，跛，重兵器）→ 逼玩家改打大开大合 |
| 六 | 大漠孤城 | 快，尖锐 | 痛、怒 | **同路人**（同龄）→ 会预判你的连段 |
| 七 | 城下 | **慢歌**，全场唯一抒情曲 | 静、凄 | **唱歌的女人**（年轻）→ 人声干扰带偏拍子 |
| 八 | 闯营 | 快，冲锋 | 势起 | 兵阵。全游戏唯一以一敌众 |
| 九 | 城楼 | 最长最烈 → 军鼓压过 → 静音 → 回归 | 决 | **韩铎**。两种节奏的对撞 |

### 路上四个人（每个都挂在主线上）

1. **竹林 · 乐师**（中年，斯文，用毒）。韩铎请来辨认追的人是否货真价实——
   他是极少数当年听过这门武学的人。嗓子早被毒废唱不出声，他来一半是差事，
   **一半是想再听一次**。
2. **雪山 · 老将**（老，跛，重兵器）。**当年在江南领队的就是他**，那晚的鼓令是他下的。
   沈砚不是靠脸认出他，是**靠节奏**——序幕在这里第一次得到回报。他给沈砚倒了碗酒，
   说了句"你父亲当时也没求饶"，然后拿起兵器。
3. **大漠 · 同路人**（与沈砚同龄）。**师父死后出现**，玩家最孤的时候。韩铎派他来的，
   但不是来杀，是来看——要抓活口先得摸清这人怎么打怎么奏。一路同行、吃饭、并肩
   打过一场，**那些都是真的，也都是差事**。
4. **城下 · 唱歌的女人**（年轻，卖唱出身）。韩铎多年来找人试着复原残谱，她是其中之一，
   被养在军中日复一日唱那些残缺的句子。**她唱的就是沈砚家的东西**，唱了很多年，
   半对半错。她跟着正在播放的曲子唱，稍稍错开拐向另一个调，**把你的拍子带跑**。
   你越想跟着音乐打越乱——**你必须学会不听她的**。

## 与《曲中剑》的差异

《曲中剑》（腾讯天美应届生团队，2022）是这个想法最直接的前身：水墨风、横版、
一首古曲一个 BOSS、漫画过场，TapTap 9.4/10。**必须能清楚说出我们的不同，
否则这个项目没有存在理由。**

### 它被玩家批评了什么

- 玩法过于简单——"缺乏复杂谱面和判定系统，任意位置点或长按即可"，被类比为
  《节奏天国》而非正经音游
- 与《节奏天国：武士》相似，被质疑创意借鉴
- **拍子之外角色没有动画**
- **攻击方向单调**
- 缺乏正反馈
- 内容极少（本身是比赛作品）
- 玩家更喜欢原曲，而非改编版

### 六条差异

| # | 差异 | 对应它的哪个短板 |
|---|---|---|
| 1 | **它是节拍反应游戏，我们是战斗游戏。** 它的核心动词是「格挡」——在正确时间点屏幕接住攻击。我们是主动进攻为主 + 读招防守 + 副歌爆发 | 玩法过于简单 |
| 2 | **武器 = 节奏型，这一整个维度它没有。** 单刀四分音符 / 双刀十六分音符 / 重剑二分音符，同一首歌换武器手上做的事完全不同 | 攻击方向单调 |
| 3 | **打击感。** 量化到音符时值的顿帧、低频、分部位受击反馈 | 拍子之外没有动画、缺乏正反馈 |
| 4 | **音乐方向是结构性差异。** 它用古典名曲（《梅花三弄》《十面埋伏》），**古琴曲没有主歌副歌、没有 drop**，"曲式即战斗结构"在它身上根本无法成立。我们用流行古风，曲式本身就是战斗曲线 | 玩家更喜欢原曲 |
| 5 | **成长循环。** 打赢一个人学会他的节奏（MH 式循环）。它是一首歌一关，打完就完 | 内容少、玩不久 |
| 6 | **平台与体量。** PC/Steam + 导歌模式（内容无限）。它是移动端小体量比赛作品 | 内容极少 |

### 结论

**它没做大不是方向错了，是玩法太浅、体量太小。** 一个被市场验证过（9.4 分）
却留着巨大空白的方向，是最好的局面。

### 一个跨竞品的观察

《曲中剑》是 2D、Dead as Disco 是 3D，**两者被批评的却是同一件事**：
玩法深度不足（"攻击方向单调" / "一直按左键"）。

**视角不是这个品类的成败因素，玩法深度才是。**
因此视角选择的标准应该是：**哪种视角能让开发预算最大程度花在深度上。**

## Visual Identity Anchor

> 待 `/art-bible` 正式确立。以下为概念阶段的方向锚点。

**方向**：**江湖，不是戏台**。流行古风的气质——快意恩仇、白衣仗剑、雨中打斗。
不走戏曲脸谱路线（走窄了），不走赛博/霓虹（品类里全是这个）。

### 视角：未定，由 Demo 对比决定

侧视对峙这个前提已定（读招可读性要求），但**画面维度未定**。三个候选：

| 方案 | 沉浸感 | 额外学习成本 | 风险 |
|---|---|---|---|
| A. 2D 角色 + 多层视差场景 | 中 | 基本没有 | 低；但可能像《曲中剑》一样"平" |
| B. 3D 场景与角色 + **受控侧视镜头**（只推近、微移、转场，不自由旋转） | 高 | 建模、绑骨、动画、镜头 | 中高；镜头受控保住了读招可读性 |
| C. 全 3D 越肩自由镜头 | 最高 | 以上全部 + 锁定系统 | 高；《燕云》被批"判定与锁定迷"即栽于此 |

**决策方式：做 A 和 B 两个可玩 Demo，实际手感对比后再定。**
纸面讨论无法回答"沉浸感值不值这个成本"。

**注**：原型的战斗验证用色块即可，与本决策解耦。
A 和 B 共享侧视前提，只有 C 需要推倒重来。

**一句话视觉规则**：**每一场都是一幅不同的山河，而不是一个换了灯光的擂台。**

**支撑原则**：
1. **场景随歌曲推进而变形**。BOSS 战不是在一个台子上打完——竹林、雨夜渡口、
   雪山驿道、大漠孤城、城楼之巅。（Dead as Disco 被批场景变化不足，像拳击台。）
   *设计测试*：如果一场战斗从头到尾场景没变，它就还没做完。
2. **全世界都在打拍子**。灯笼晃、雨滴落、竹叶颤、衣袂动、UI 脉动——
   即使玩家音感不好，眼睛也能跟上。（学 Hi-Fi Rush。）
   *设计测试*：静帧截图里看不出节奏，就是没做够。
3. **两种调子并存**。主体硬派热血（快意恩仇、鼓点重），关键情感段落写意苍凉
   （雨、留白、余韵）。落差本身就是情感。

**色彩哲学**：以水墨的黑白灰为底，每一场用一个主色调压场
（竹林青、雪山白、大漠赭、雨夜靛）。命中与踩准的瞬间是唯一的高饱和亮色。

## Technical Considerations

| Consideration | Assessment |
| ---- | ---- |
| **Recommended Engine** | **Godot 4**。轻量、免费、上手快、PC 导出成熟；用户为第一款游戏，Godot 学习曲线最友好 |
| **Key Technical Challenges** | ① 顿帧与节奏的冲突（见下）② 音频延迟与判定精度 ③ 打击感调校 |
| **Art Style** | 待定，倾向 2D 或 2.5D 风格化水墨。AI 辅助生成资产 |
| **Art Pipeline Complexity** | Medium。用户非专业画师，依赖 AI 生成 + 后期调整 |
| **Audio Needs** | **Music-heavy + Adaptive**。音乐是产品本身，不是背景 |
| **Networking** | None |
| **Content Volume** | Full vision: 9 场战斗 / 9 首曲子 / 4 把武器 / 约 4–6 小时主线 + 自由模式无限 |
| **Procedural Systems** | 导歌模式需要基础 BPM 同步（可参考 Dead as Disco 的手动输入 BPM + 分段方案） |

### 必须遵守的技术约束

1. **判定的时间基准必须是音频播放位置，不能是渲染帧。**
   60fps 一帧 = 16.7ms，而音游 Perfect 窗口通常是 ±16–30ms。用帧计时判定精度天然废掉一半。
2. **必须提供校准偏移（global offset）设置**，不同设备音频延迟差异很大。
3. **顿帧只能是视觉层的，音乐绝不能停。** 音乐一停整首歌就废。
4. **顿帧时长以音符时值定义**（120 BPM 参考值）：

   | 命中类型 | 顿帧 | 实际时长 |
   | ---- | ---- | ---- |
   | 轻击 | 1/16 拍 | 0.031 秒 |
   | 重击 | 1/8 拍 | 0.063 秒 |
   | 破防 | 1/4 拍 | 0.125 秒 |
   | 终结斩（气满触发，不锁定拍点） | 3/8 拍（原型试玩后从 1/2 拍调轻） | 0.188 秒 |

   终结斩最初按半拍设计，原型试玩发现若在乐句中间触发会打断整体律动感；
   调轻到 3/8 拍后仍能明显感知"沉"，但不再是硬性打断。触发时机保留为
   "气满即可"（当成随时可能降临的奖励），不强制锁定在乐句末尾。

### 实测数据（2026-08-31，节拍时钟原型）

在开发机（RTX 5070 Laptop，165Hz，Godot 4.7.2）上实测：

| 指标 | 实测值 | 结论 |
|---|---|---|
| `AudioServer.get_output_latency()` | **10.00 ms** | 低于 Godot 默认 15ms，无需调整延迟设置 |
| 混音率 | 48000 Hz | 正常 |
| 渲染帧计时 30 秒累计漂移 | **+12.4 ms** | 线性累积；3.5 分钟的歌会漂到约 87ms。**证实了不能用帧计时** |
| 时钟抖动丢弃率 | 约 15%（749 / ~4950 帧） | 单调性防抖正常工作；后续可改进为平滑外推 |
| 人工敲击平均偏移 | **+34.3 ms** | 该机器 + 玩家的校准偏移基准 |
| 人工敲击波动（标准差） | **±29.5 ms** | **最重要的一个数，见下** |

### 判定窗口（由实测推导，非拍脑袋）

玩家敲击的固有波动是 **±29.5 ms**，而标准音游 Perfect 窗口是 ±16–30 ms——
**按标准音游的判定，开发者本人都打不准。** 这是人类 + 键盘 + 系统的固有抖动，
不是技术能消除的。因此：

| 判定 | 标准音游 | **本项目** |
|---|---|---|
| Perfect | ±16–30 ms | **±60 ms** |
| Good | ±70 ms | **±120 ms** |
| 未命中 | miss，扣血 | **只是伤害低、不进连段，不扣血** |

这与 Pillar 1 一致，且现在有实测依据。

### 两种敲击手法（观察，待做校准选项）

- **抬手敲击**：行程长，手上有真实冲击反馈，**打击感更强**，但落点方差大
- **贴键按压**：行程短，反馈弱，但更准

《节奏医生》提供了这个选项。我们不做成"模式选择"（会让玩家被自己的选择惩罚），
而是**靠宽判定自然容纳两种**；校准工具里可提供两个档位的默认偏移。

### 打击感实现要点（来自调研）

- **"改变对手动作"是打击感最核心之处**，优先级高于音效和特效
- 受击特效强度约为攻击特效的 **1.2 倍**，但**持续时间更短**
- 受击动作按**命中部位**区分
- 震屏只调 **Pitch / Yaw**，**绝不动 Roll**（会晕）；理想状态是"视觉可感知但战斗中完全注意不到"
- 音效音量优先级：**格挡音 > 击中音 > 攻击音 > 喊话**
- 物理攻击音三段结构：**破空声 → 碰撞声 → 液体飞溅声**
- 特效时间结构：蓄力 0.5–2 秒 → 爆发 0.1–0.3 秒 → 消退 1–3 秒
- **音效必须用真实兵器音源**，不能替换成乐器音色（会牺牲打击感）。
  乐器泛音只作为极低音量的"缝合层"，玩家应意识不到它的存在

### 踩准拍子的奖励（不是换声音，是同一个声音更狠）

| | 没踩上 | 踩准了 |
| ---- | ---- | ---- |
| 顿帧 | 短 | **更长，卡得更实** |
| 低频 | 一般 | **更重** |
| 震动 | 轻 | **更强** |
| 特效 | 普通 | **更炸** |
| 伤害/连段 | 低，不进连段 | 高，连段累积 |

## Risks and Open Questions

### Design Risks
- **顿帧量化到音符时值这个方案未经任何游戏验证**，是推理产物。若不成立，
  "打击感 + 踩点感"的核心承诺就落空
- 打击感与节奏感可能无法真正融为一体，变成两层割裂的体验
- 曲目情绪编排若失衡，会重蹈 Dead as Disco"三小时就腻"的覆辙

### Technical Risks
- 音频延迟与判定精度处理不当，会造成"说不上哪不对但就是难受"的手感
- 动作游戏手感调校依赖经验，开发者为第一次做游戏
- 导歌模式的 BPM 同步对变速曲目的处理

### Market Risks
- 节奏战斗品类竞争者已有 Dead as Disco、Hi-Fi Rush 等成熟作品
- 古风题材在海外市场的接受度未知（但同时也是最大的差异化优势——
  **该品类目前无任何东方题材作品**）

### Scope Risks
- 9 场战斗 / 9 首曲子对个人开发者是重负担（武器数量已从 4 把砍到 1 把，见 Pillar 4）
- 音乐制作（原创或 AI 生成）的质量是留存关键，且工作量不可压缩
- **人工制谱的工时未知**：原型阶段一首歌只编了 14 段（约 112 秒），完整一首
  歌、9 首歌的制谱总工时需要在正式生产阶段实测（自动生成谱面已确认不可行，
  见 `prototypes/rhythm-feel/README.md` 发现 4）

### Open Questions
- ~~顿帧量化方案是否成立？~~ ✅ 原型已验证，终结斩顿帧从 1/2 拍调轻到 3/8 拍
- ~~单刀砍在拍子上到底爽不爽？~~ ✅ 原型已验证（真实曲目 + 手工谱面）
- ~~一首歌就是一场战斗，曲式能否驱动战斗结构？~~ ✅ 原型已验证
- ~~换武器是否真的等于换了一种玩法？~~ ❌ 已证伪并推翻，改为"对手改变节奏"（Pillar 4）
- 主角具体使用的武学与武器命名（"板眼"体系的招式命名，现在只需定一把）
- 各角色姓名（韩铎、沈砚、段拙已定，路上四人待定）
- 美术风格的具体落点 → `/art-bible`
- **视角**：2D 与 3D 受控侧视对比 demo 尚未开始

## MVP Definition

**Core hypothesis**：**把一首歌打出来，爽不爽？**

即：一刀砍在拍子上时，物理上的沉和音乐上的准是否能合成同一种快感。

**Required for MVP**（已在 `prototypes/rhythm-feel/` 完成，见其 README）：
1. **1 把武器**（单刀。武器不再是差异化维度，见 Pillar 4）
2. **1 首真实曲目**（《牵丝戏》，人工编谱 14 段 / 137 个事件）
3. **1 个敌人**（谱面驱动出招，起手预兆 + 音符轨道双重提示）
4. **完整的手感三件套**：量化到音符时值的顿帧、受击反馈、踩拍增益 ✅
5. 判定以音频播放位置为基准 + 实时校准偏移 ✅

**Explicitly NOT in MVP**：
- 剧情、过场、对话
- 多武器、多关卡、多曲目
- 菜单、UI 打磨、存档
- 美术打磨（用色块和简图即可）
- 成长系统、导歌功能

**验证顺序（已完成）**：
1. ~~节拍时钟准不准~~ ✅ 已验证
2. ~~单刀 + 一首歌 + 一个敌人 → 砍在拍子上爽不爽？~~ ✅ 已验证
3. ~~曲式驱动战斗结构（一首歌就是一场战斗）~~ ✅ 已验证
4. ~~换武器是不是真的换了一种玩法？~~ ❌ 证伪，改为对手驱动差异化（Pillar 4）

**下一步验证**：
5. **视角对比 Demo**：同一套战斗逻辑，做 2D 版和 3D 受控侧视版各一个 →
   **3D 的沉浸感值不值那个成本？**
6. **对手干扰机制原型**：任选一种（如人声唱偏拍子）做一个可玩验证
7. **完整制谱工时评估**：用 `chart_editor` 编完一首完整曲目，估算 9 首歌总工时

核心手感假设已经过验证，项目可以进入正式设计阶段；第 5–7 项决定具体怎么做。

### Scope Tiers

| Tier | Content | Features | Timeline |
| ---- | ---- | ---- | ---- |
| **MVP（概念原型）** | 1 敌人 / 1 曲 / 1 武器 | 核心手感循环 | 2–4 周 |
| **Vertical Slice** | 1 完整 BOSS 战（含曲式分段、破防爆发、场景变化） | 核心 + 2 把武器 + 基础 UI | 6–10 周 |
| **Alpha** | 全 9 场，占位美术 | 全部功能，粗糙；含导歌模式 | 5–7 个月 |
| **Full Vision** | 9 场完整内容 + 4 武器 + 自由模式 | 全功能打磨 | 9–14 个月 |
